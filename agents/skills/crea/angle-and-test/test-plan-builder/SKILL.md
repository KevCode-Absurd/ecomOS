name: angle-and-test/test-plan-builder
owner: crea-paid-creative-copy
version: 1
invoke_when: an angle brief is ready and the creative side of a test needs a
  hypothesis and a pre-set win/kill rule
inputs: angle brief, metric contract delivery volume, registry of past test
  sizes for this brand
outputs: test brief with hypothesis, pack size, winner/kill rule, read window
---
Purpose: fix the test's judgment criteria before a single script is written,
so no one is tempted to move the goalposts once real numbers start coming in;
covers the creative side of the test only; MEDIA owns the budget and delivery
mechanics of the same test.

Steps
1. Write the hypothesis as one sentence: which angle or hook change is being
   tested, and which specific metric it should move (hook rate, CVR, CPA).
2. Structure the test as one persona per ad set, so a result can be
   attributed to the angle, not blurred across personas sharing a set.
3. Size the pack, how many ad variants launch at once, from this account's
   own real delivery volume using metric-read, not a fixed "always test 5"
   rule; a low-volume account needs a smaller, cleaner pack.
4. Set the winner rule and the kill rule in the same sentence as the
   hypothesis, before any creative exists, so the eventual read has no room
   for a post-hoc rationalization.
5. Set the minimum read window from the account's own delivery, enough days
   to reach a meaningful sample, not a calendar habit like "always 7 days."

Checks: rules exist before scripting starts; every number in the plan is
computed from real account data, not a template default.

Output: the test brief, handed whole into the launch checklist step.

Example: hypothesis "the price-anchor angle beats the durability angle on
CPA"; pack of 4 (2 per angle) sized to the account's 40-purchase/week volume;
winner rule is CPA 20% below target at 50+ purchases per ad.
