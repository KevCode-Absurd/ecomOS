# Write SOPs, the handbook and offboarding checklists

## Purpose
Keep operating knowledge in a live document with a named owner, not in one person's head, and never leave an exit half-done.

## Steps
1. Spot when a procedure has been asked for a third time without a written SOP.
2. Write the SOP: purpose, numbered steps with the tool used at each, and the check before it counts as done.
3. Assign one named owner and a freshness date.
4. Keep the handbook current: leave, work-from-home, code of conduct, and the POSH policy section, and confirm every employee has acknowledged it.
5. On a resignation or termination notice, run the offboarding checklist: same-day access revocation, asset return, knowledge transfer, exit interview, final settlement.

## Checks
- Every SOP has exactly one named owner, never a team name.
- Access revocation on exit happens the same day, not the same week.

## Output
The requested document: a new SOP, the updated handbook with an acknowledgement log, or a completed offboarding checklist.

## Example
A third support agent asks how to handle a wrong-size return in the same week; the pattern triggers a written SOP instead of a fourth verbal explanation.
