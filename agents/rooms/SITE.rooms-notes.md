# SITE rooms: what they show that the common tools do not

Three rooms, built from the SITE capability catalogue and the speed lab and Meta gallery patterns.

## Site and speed
Shopify's speed report and PageSpeed Insights give one lab score with generic tips, on today's page only. This room keeps the speed lab's real pattern: a fix chain measured on a mirrored copy of the live page, one step at a time, with a before-and-after filmstrip, and the same three decisions per fix (agent, developer, not now). It adds a script inventory checked against the brand's own revenue data, a page-weight budget that flags a regression the moment a deploy crosses it, and a cost-of-slowness number in rupees per month, not an industry percentage.

## Landing pages and CRO
VWO and Convert.com report test statistics well but never check whether the ad's own promise, price, guarantee and CTA still hold by checkout. This room audits that trace directly, ranks the test backlog by an expected-profit ceiling built from real evidence before anything launches, and checks a winner's return and repeat-purchase rate 60 days after it scales, since no common tool re-checks a win after the fact. It also catches a false urgency claim the moment a displayed stock count stops matching real inventory.

## Store health
This room ties together setup QA, uptime, checkout, the app and script stack, accessibility, structured data, and India's COD and RTO controls. UptimeRobot pings a URL; this room also runs a synthetic checkout. Axe and WAVE scan pages; this room groups the same violations by template and routes them to a developer brief. COD apps like RTO Shield or Level run the block-or-confirm step; this room reads the outcome back against the brand's own delivered-order history to say whether the control worked.

## Hardest data to get
Three things need a pipe the brand does not have yet: a brand-specific conversion-loss-per-second figure to price slowness in rupees, order-level attribution from a CRO test through to 60-day returns and repeat purchases, and logistics status fed back into order data so RTO can be measured by pincode rather than guessed at. Speed runs, app inventory, accessibility scans, structured data crawls and uptime checks can all be built with scripts and scheduled crawls today.
